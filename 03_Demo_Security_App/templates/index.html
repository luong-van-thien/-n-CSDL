THỰC NGHIỆM TẤN CÔNG & PHÒNG CHỐNG SQL INJECTION (MỤC 30.4)

Khảo sát cơ chế phát sinh lỗ hổng khi ghép chuỗi SQL và giải pháp phòng thủ triệt để bằng Parameterized Queries.

Kịch bản 1: Vượt qua xác thực (Authentication Bypass)

Thử Payload tấn công mẫu:
Câu lệnh SQL thực thi ngầm:
SELECT * FROM USERS WHERE username = '...'

Kịch bản 2: Trích xuất dữ liệu nhạy cảm (UNION SQLi)

Thử Payload trích xuất CSDL:
Câu lệnh SQL thực thi ngầm:

MÔ HÌNH PHÂN QUYỀN DỰA TRÊN VAI TRÒ (RBAC) (MỤC 30.3)

Mô phỏng ma trận quyền truy cập (Access Control Matrix) và chính sách kiểm soát quyền hạn theo chức vụ.

Ma Trận Quyền Truy Cập (Access Control Matrix)

Vai trò (Role) Xem Sản phẩm Chỉnh sửa Sản phẩm Xem Đơn hàng Xóa Đơn hàng Xem Lương Nhân sự Quản trị Người dùng
ADMIN (Quản trị) Có Có Có Có Có Có
MANAGER (Quản lý) Có Có Có Không Có Không
STAFF (Nhân viên) Có Không Có Không Không Không
CUSTOMER (Khách hàng) Có Không Chỉ đơn của mình (RLS) Không Không Không

Trình Giả Lập Thử Nghiệm Quyền Hạn Thực Tế

Vui lòng chọn vai trò và hành động để kiểm thử cơ chế phân quyền.

KỊCH BẢN BẢO MẬT TRÊN MICROSOFT SQL SERVER

Các lệnh T-SQL tiêu chuẩn triển khai kiểm soát quyền truy cập, Row-Level Security (RLS) và Dynamic Data Masking (DDM).

T-SQL: Triển khai Cấp quyền (GRANT/REVOKE), RLS và Data Masking

-- ============================================================================
-- KỊCH BẢN BẢO MẬT CHUYÊN SÂU TRÊN MICROSOFT SQL SERVER 2022
-- ============================================================================
USE TechStoreDB;
GO

-- 1. TẠO CÁC ROLE TRONG CSDL VÀ PHÂN QUYỀN DAC
CREATE ROLE Role_NhanVienBanHang;
CREATE ROLE Role_QuanLyCuaHang;

-- Cấp quyền SELECT trên bảng sản phẩm và khách hàng cho nhân viên bán hàng
GRANT SELECT ON SAN_PHAM TO Role_NhanVienBanHang;
GRANT SELECT, INSERT ON DON_HANG TO Role_NhanVienBanHang;
GRANT SELECT, INSERT ON CHI_TIET_DON_HANG TO Role_NhanVienBanHang;

-- CẤM (DENY) nhân viên bán hàng xem cột Lương của nhân viên
DENY SELECT ON NHAN_VIEN(LuongCoBan) TO Role_NhanVienBanHang;

-- Quản lý cửa hàng có thêm quyền cập nhật giá bán sản phẩm
GRANT SELECT, UPDATE(GiaBan, SoLuongTon) ON SAN_PHAM TO Role_QuanLyCuaHang;
GO

-- 2. TRIỂN KHAI DYNAMIC DATA MASKING (DDM) CHE DỮ LIỆU NHẠY CẢM
-- Che số điện thoại: Chỉ hiển thị 3 ký tự đầu và 2 ký tự cuối
ALTER TABLE KHACH_HANG
ALTER COLUMN SoDienThoai ADD MASKED WITH (FUNCTION = 'partial(3, "XXXXXX", 2)');

-- Che Email theo định dạng chuẩn email: aXXX@gmail.com
ALTER TABLE KHACH_HANG
ALTER COLUMN Email ADD MASKED WITH (FUNCTION = 'email()');
GO

-- 3. TRIỂN KHAI ROW-LEVEL SECURITY (RLS) CÔ LẬP ĐƠN HÀNG CỦA KHÁCH HÀNG
-- Tạo hàm vị từ kiểm tra danh tính người dùng đang thực thi truy vấn
CREATE SCHEMA Security;
GO

CREATE FUNCTION Security.fn_SecurityPredicateKhachHang(@MaKH VARCHAR(20))
RETURNS TABLE
WITH SCHEMABINDING
AS
RETURN SELECT 1 AS fn_access_result
WHERE 
    IS_MEMBER('Role_QuanLyCuaHang') = 1 
    OR IS_MEMBER('db_owner') = 1
    OR @MaKH = CAST(SESSION_CONTEXT(N'CurrentUser_MaKH') AS VARCHAR(20));
GO

-- Áp dụng chính sách bảo mật lọc hàng (Filter Predicate) lên bảng DON_HANG
CREATE SECURITY POLICY Security.DonHangSecurityPolicy
ADD FILTER PREDICATE Security.fn_SecurityPredicateKhachHang(MaKH) ON dbo.DON_HANG
WITH (STATE = ON);
GO
